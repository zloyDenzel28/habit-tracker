# Трекер полезных привычек

Пет-проект: приложение для отслеживания привычек. Пользователь заводит привычку с расписанием (дни недели + время) и длительностью, бот напоминает о ней в назначенное время, позволяет отложить или пропустить выполнение, а после окончания — подтвердить, что привычка выполнена. История выполнений превращается в стрики и статистику.

Полная спецификация — в [`docs/requirements.md`](docs/requirements.md), он источник истины. Заметки о ходе разработки и архитектурные инварианты — в [`HANDOFF.md`](HANDOFF.md) и [`CLAUDE.md`](CLAUDE.md).

Как устроено внутри: [`docs/architecture.md`](docs/architecture.md) — C4 и сиквенсы ключевых сценариев, [`docs/erd.md`](docs/erd.md) — модель данных. Диаграммы на PlantUML, GitHub их в markdown не рендерит — чем смотреть картинками, написано в начале `architecture.md`.

## Как поднять

Всё приложение запускается только через Docker Compose — локальной установки Python/Node не требуется.

1. Скопировать `.env.example` в `.env` и заполнить значения:
   - `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` — можно оставить как есть для локального запуска.
   - `DATABASE_URL` — уже указывает на сервис `db` в compose-сети, менять не нужно.
   - `TELEGRAM_BOT_TOKEN` — токен бота от `@BotFather`. Можно оставить пустым: `api` и `worker` поднимутся без него, а `bot` запустится в режиме заглушки и напишет об этом в лог.
   - `TELEGRAM_BOT_USERNAME` — юзернейм того же бота без `@`, нужен только для кликабельной ссылки на бота в «Настройках» фронта.
   - `DEV_AUTH` — `true` включает вход без Telegram Login Widget, удобно для локальной разработки.
   - `SCHEDULER_TICK_SECONDS` — период опроса БД планировщиком. На отладке можно поставить `5`, чтобы прогнать жизненный цикл occurrence за пару минут вместо часа (после правки перечитывается только через `docker compose up -d worker`, обычный `restart` переменные окружения не подхватывает).
   - `SEED_TELEGRAM_ID`, `SEED_TIMEZONE` — telegram ID и таймзона (IANA) сид-пользователя, которого создают фикстуры; нужны, чтобы реальные уведомления приходили в свой чат и стрики считались в своей таймзоне.
2. Поднять всё:

   ```bash
   docker compose up --build
   ```

3. При первом запуске можно засеять тестовые данные:

   ```bash
   docker compose exec api python -m app.fixtures.seed
   ```

Фронт будет доступен на `http://localhost:5173`, API — на `http://localhost:8000`.

## Из чего состоит

| Сервис | Роль |
|---|---|
| `db` | PostgreSQL 16 — хранилище данных |
| `migrate` | одноразовый сервис, применяет миграции Alembic перед стартом остальных процессов и завершается |
| `api` | FastAPI — REST для фронта |
| `worker` | APScheduler в отдельном процессе — периодические задачи: генерация occurrences по расписанию, уведомления, догоняющие пинги, закрытие дня |
| `bot` | aiogram в режиме polling — принимает нажатия кнопок в Telegram и записывает результат в БД |
| `web` | React + Vite + TypeScript, дев-сервер с hot reload |

`api`, `worker` и `bot` собираются из одного образа (`backend/`) и делят общие модели и сервисный слой — различаются только командой запуска. Бизнес-логика (переходы статусов, расчёт стриков) живёт в сервисном слое, поэтому одно и то же действие пользователя работает одинаково что из веба, что из Telegram.

## Куда смотреть при отладке

```bash
docker compose logs -f worker      # джобы планировщика: генерация occurrences, уведомления, закрытие дня
docker compose logs -f bot         # нажатия кнопок в Telegram
docker compose logs -f api         # запросы фронта
docker compose exec db psql -U postgres -d habits   # прямой доступ к БД
docker compose exec api pytest     # юнит-тесты сервисного слоя
```

Полный список команд, включая работу с миграциями Alembic, — в разделе «Команды» файла [`CLAUDE.md`](CLAUDE.md).
